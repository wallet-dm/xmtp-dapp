# Capability map

Changes I want to make to my factory, ranked. Started in L2 on Day 1, finished on Day 2 morning, and built from in the three feature labs.

## The layer each change touches

Naming the layer is most of the thinking, because it decides what file you open.

| Layer       | You are changing                             | Shape of the change                                                       |
| ----------- | -------------------------------------------- | ------------------------------------------------------------------------- |
| **Agent**   | What an agent knows and how it judges        | A prompt template, an `agent.toml`                                        |
| **Formula** | What steps a job has and what they depend on | A `*.formula.toml`, often extending an existing one                       |
| **Order**   | When something happens with no human present | An `order.toml` with a `cooldown`, `cron`, `condition` or `event` trigger |

If a change does not fit any of the three, it is probably a change to your _project_ rather than to your factory. Write it down somewhere else.

## Where these rows came from

Note the evidence behind each row, so a future you can tell a real finding from a good idea.

- **The gate bounced a bead of mine, and its feedback said:** nothing yet — no bead has been slung, so no gate has fired. The nearest real datum is the opposite failure: xd-1vg was accepted into the queue with a title and no description, and no gate objected (row 4).
- **A reviewer produced an opinion rather than a verdict, because it had nothing to cite:** structurally guaranteed today — `mol-architect-review`'s first step loads `docs/decision-records/*.md`, and that directory does not exist in this rig. Any verdict the architect writes can only be taste (row 2).
- **I read a diff the factory wrote and would have written it differently, because:** the factory has written no diffs yet. The human history carries the same lesson though: `fix(lint): remove unused variable` and `chore(deps): fix linter` are lint fixes landing as follow-up commits — checks arriving after merge instead of in front of it (rows 1, 3).
- **Something ran that should not have, or did not run that should have:** `npm run format:check` fails on 5 files right now (including the factory's own manifests) and nothing in the factory runs it; the refinery's check-command vars default to empty = skip, so typecheck/lint/test run nowhere on the merge path (row 1); and no clock or event watches the react-sdk import count, which is the project's entire success metric (row 5). Meanwhile the two orders that do run write to a log nothing reads.

## Out of scope, deliberately

Things you decided not to do, and why. This section stops you re-litigating the same idea in three weeks.

- **Multi-vendor review (`multi-vendor-rig`).** Cross-model review is real, but adding second opinions before the single reviewer has a document to cite (row 2) multiplies opinions, not verdicts. Revisit after rows 1–3 have survived a week.
- **Cypress e2e and the mobile smoke test in the automated merge gate.** `npm run e2e:headless` needs a wallet and the XMTP dev network in a headless environment — flaky as a blocking check today. It stays a human step at Gate 2; automate only after the Vitest gate (row 1) has proven stable.
- **Group chats and other new XMTP features.** Project scope, not factory scope — and PROJECT_MANIFEST defers them until the browser-sdk migration completes anyway.
- **Self-improvement loop (option 6).** The loop reads evidence the factory produces about itself, and after one day there is one open bead and zero reviews to read. Worth doing the week the review lanes (rows 1, 2, 4) start generating bounces.
- **Removing the mayor's human approval on PRs.** At the current trust level the human gate _is_ the safety system. Re-rank only when the map's top three rows have each caught a real defect unaided.
